What is EduFlow

University registration platforms serve students on phones between classes, advisors on tablets during office hours, and registrars managing batch workflows on desktop, all at once and all with different needs.

EduFlow gives teams a shared visual language, accessible-by-default components, and a governance model that scales across departments without falling apart.

Design tokens

Design tokens are where the system starts. Instead of hardcoding values, tokens give decisions a name and push them everywhere automatically. Update one token and every button, badge, and header that references it updates too.

In a large organization, different teams often solve the same problem differently. Tokens give each of those decisions a single definition.

Atomic design

Atoms

The smallest building blocks: buttons, inputs, icons, and badges. Building accessibility into the atoms means larger components start from accessible parts, though each combination still needs its own checks.

Molecules

Atoms combined into single-purpose units. A search bar, a course card, and a labeled input with an error state. One job each, reusable anywhere.

Organisms

Substantial enough to accomplish something meaningful, modular enough for multiple teams to share across different products. Navigation sidebars, content grids, and form sections.

Templates

Layout blueprints that define structure without prescribing content. Teams start from a template and spend their energy on the product problem.

AI-powered components

These components explore what registration looks like when AI is useful. AI serves as a layer that supports students in decision-making and helps advisors focus their efforts.

  • Course Recommendations: Suggests courses based on academic history, major requirements, and peer patterns. An explainability layer tells you why each course was recommended and lets you dismiss or give feedback.
  • Dynamic Schedule Planner: Designed for wearable haptic reminders, estimated walk times between buildings, and conflict detection before problems come up.
  • Advisor Analytics Dashboard: Flags at-risk signals like a declining GPA, missed appointments, or no contact in 30 days, so advisors can prioritize their caseload without jumping between tools.

Accessibility

Accessibility is built into every layer of EduFlow. Tokens enforce color contrast. Components ship with keyboard navigation and ARIA support. I checked the documentation site with WAVE as I built it and fixed what it flagged.

WCAG 2.2 AA is the minimum. Every student has to register for classes, so an inaccessible step in registration may keep someone from enrolling.

AI patterns

Every AI feature had to clear one bar: would users trust it? Four principles drove every decision: transparency (users always know when AI is involved), control (AI suggests, users decide), explainability (recommendations come with reasons), and clear boundaries (users can tell what they did from what the system did).

When the AI can’t help, the system says so and hands control back.

Governance

EduFlow defines four groups: the core team, platform teams, delivery squads, and external contributors. Changes flow from proposal to stable release through a defined process, and the system specifies that a token update reaches every product using it.

Nothing ships without documentation. Breaking changes require 90 days’ notice and a migration guide.

About this project

EduFlow was developed for a Managing UX Teams graduate course. The brief called for a complete design system: components, foundations, governance, AI patterns, accessibility guidelines, and a contribution model for a university navigating digital transformation.

The initial idea came from a teammate. I led the system from there: the atomic design hierarchy, token specifications, XAI principles, and governance model, all defined before anything was generated. I then built the documentation site, writing the prompts that turned those decisions into the site.
